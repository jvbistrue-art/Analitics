# ТЗ на разработку AAC-решения для запроса Ольги Логопеда

## 1. Назначение документа

Документ описывает техническое задание на разработку русскоязычного решения альтернативной и дополнительной коммуникации (AAC), которое покрывает потребность, выявленную при анализе Grid 3, Look to Learn, Cboard и LINKa:

- дать человеку с нарушением речи способ выражать базовые и расширенные потребности;
- поддержать работу логопеда/специалиста с карточками, фразами, обучением выбору и постепенным развитием коммуникации;
- обеспечить русский интерфейс и русскую озвучку;
- предусмотреть доступ через сенсорный экран, мышь, клавиатуру/кнопки и, как расширение, айтрекер;
- позволить семье и специалисту быстро настраивать словарь под конкретного пользователя.

## 2. Цель продукта

Создать доступное AAC-приложение для детей и взрослых с нарушениями речи и/или моторики, которое позволяет:

1. выбирать карточки с пиктограммами, фотографиями или текстом;
2. собирать фразу из выбранных элементов;
3. озвучивать выбранную карточку или собранную фразу русским синтезатором речи;
4. настраивать индивидуальные наборы карточек без участия разработчика;
5. использовать приложение на доступном устройстве: планшет, ноутбук, интерактивная панель;
6. расширяться до специальных способов доступа: сканирование, внешняя кнопка, управление взглядом.

## 3. Целевые пользователи

### 3.1. Основной пользователь

Человек с ограниченной или отсутствующей устной речью:

- ребенок с РАС, ДЦП, тяжелой дизартрией, анартрией, задержкой речевого развития;
- взрослый после инсульта, травмы, неврологического заболевания;
- пользователь, которому нужна поддержка в выборе, выражении просьб, ответов, эмоций и бытовых потребностей.

### 3.2. Специалист

Логопед, дефектолог, педагог, эрготерапевт или тьютор, который:

- создает и адаптирует наборы карточек;
- моделирует коммуникацию во время занятия;
- отслеживает прогресс;
- подбирает размер сетки, способ доступа и словарь.

### 3.3. Семья / сопровождающий

Родитель, родственник или ассистент, который:

- использует приложение дома;
- добавляет бытовые карточки и фотографии;
- помогает переносить навык из занятия в повседневную коммуникацию.

### 3.4. Администратор учреждения

Сотрудник центра/школы, который:

- управляет профилями нескольких пользователей;
- следит за резервными копиями;
- выдает доступ специалистам.

## 4. Ключевые сценарии

### 4.1. Быстрый выбор карточки

Пользователь открывает доску "Еда", выбирает карточку "пить", приложение озвучивает "Я хочу пить".

Критерий успеха: выбор и озвучивание происходят без перехода в режим редактирования, с крупными элементами и минимальным количеством действий.

### 4.2. Сбор фразы

Пользователь выбирает последовательно "я", "хочу", "играть", "мяч", затем нажимает строку фразы. Приложение озвучивает всю фразу.

Критерий успеха: выбранные элементы видны в строке фразы, их можно удалить по одному или очистить все сразу.

### 4.3. Ответ на вопрос логопеда

Специалист открывает доску с вариантами "да", "нет", "не знаю", "еще", "стоп". Пользователь выбирает ответ.

Критерий успеха: доска запускается быстро, карточки читаемы с расстояния занятия, ответ озвучивается и визуально подтверждается.

### 4.4. Настройка индивидуального словаря

Специалист или родитель добавляет карточку "мама":

- вводит подпись;
- выбирает пиктограмму или загружает фото;
- задает фразу для озвучивания;
- выбирает категорию;
- сохраняет карточку.

Критерий успеха: новая карточка появляется на выбранной доске без перезапуска приложения.

### 4.5. Использование фотографий реального окружения

Родитель добавляет фотографии любимой кружки, игрушки, комнаты, членов семьи.

Критерий успеха: фотографии можно загрузить с устройства, обрезать/заменить, использовать на карточках.

### 4.6. Настройка доступа под моторику

Специалист выбирает размер сетки 2x2, 3x3, 4x4 или 5x5, увеличивает паузу перед повторным нажатием и включает подтверждение выбора.

Критерий успеха: пользователь с неточными движениями может выбирать карточки без частых случайных срабатываний.

### 4.7. Сканирование одной кнопкой

Пользователь не может точно нажимать на экран, но может активировать одну кнопку. Приложение последовательно подсвечивает группы/карточки, пользователь подтверждает выбор кнопкой.

Критерий успеха: можно настроить скорость сканирования, звук/визуальную подсветку, порядок обхода элементов.

### 4.8. Пробный eye-gaze режим

Пользователь смотрит на карточку заданное время, карточка подсвечивается и выбирается после dwell-паузы.

Критерий успеха: dwell-время настраивается, есть визуальный индикатор удержания взгляда, случайный краткий взгляд не приводит к выбору.

## 5. Объем MVP

MVP должен закрывать базовую коммуникацию и настройку словаря без сложной аппаратной интеграции.

### 5.1. Входит в MVP

- Веб-приложение, работающее на desktop/tablet в современных браузерах.
- Русский интерфейс.
- Профиль одного или нескольких пользователей на одном устройстве.
- Доски карточек с категориями.
- Карточки трех типов:
  - текстовая карточка;
  - карточка с пиктограммой;
  - карточка с пользовательской фотографией.
- Строка фразы.
- Озвучивание карточки и всей фразы.
- Настройки сетки: 2x2, 3x3, 4x4, 5x5.
- Настройки доступности:
  - размер карточек;
  - цветовая тема;
  - задержка повторного нажатия;
  - подтверждение выбора;
  - полноэкранный режим.
- Режим редактирования досок и карточек.
- Импорт/экспорт профиля в файл.
- Локальное хранение данных на устройстве.
- Базовая статистика использования: какие карточки выбирались, когда, сколько раз.

### 5.2. Не входит в MVP

- Полноценная облачная синхронизация между устройствами.
- Маркетплейс готовых словарей.
- Платежи и лицензирование.
- Сложная ролевая модель учреждения.
- Нативные приложения iOS/Android.
- Полная интеграция с конкретными айтрекерами на уровне SDK.
- Автоматическая диагностика готовности к AAC.

### 5.3. Расширения после MVP

- Сканирование одной/двумя кнопками.
- Eye-gaze режим через веб-камеру или через совместимые внешние средства ввода.
- Библиотека готовых наборов: "еда", "туалет", "боль", "эмоции", "занятие", "школа", "игра".
- Облачные профили и совместное редактирование логопедом/родителем.
- Экспорт отчетов для занятий.
- Поддержка нескольких языков.
- Интеграция с внешними библиотеками пиктограмм по лицензии.

## 7. Нефункциональные требования

### 7.1. Доступность

- Интерфейс должен работать с крупными интерактивными областями.
- Минимальный размер активной карточки в MVP: 80x80 px на планшете; рекомендуемый размер для 2x2/3x3 — больше.
- Цвет не должен быть единственным способом различения состояния.
- Все интерактивные элементы должны иметь видимый фокус.
- Должна быть возможность включить высококонтрастную тему.
- Приложение должно поддерживать работу в полноэкранном режиме браузера.
- Ключевые действия не должны требовать точных жестов вроде drag-and-drop в пользовательском режиме.

### 7.2. Производительность

- Открытие домашней доски после загрузки приложения: до 3 секунд на целевом устройстве среднего класса.
- Переключение между досками: до 500 мс при локальном хранении.
- Озвучивание должно стартовать без заметной задержки после выбора, если TTS доступен.
- Приложение должно устойчиво работать с профилем до 1 000 карточек в MVP.

### 7.3. Надежность

- Потеря сети не должна блокировать уже созданные локальные доски.
- Данные профиля не должны теряться при закрытии вкладки.
- Импорт профиля должен валидироваться до записи в хранилище.
- При ошибке TTS пользователь должен видеть понятное сообщение и возможность продолжить без озвучки.

### 7.4. Безопасность и приватность

- Фотографии и профили по умолчанию хранятся локально.
- Облачные функции, если появятся после MVP, должны включаться явно.
- Экспорт профиля должен предупреждать, что файл может содержать персональные данные и фотографии.
- Для детских профилей нельзя добавлять внешнюю публикацию досок без подтверждения взрослого.

### 7.5. Совместимость

MVP должен поддерживать актуальные версии:

- Chrome / Chromium;
- Microsoft Edge;
- Safari на iPadOS как целевой браузер для проверки, если используется Web Speech API с ограничениями;
- Android Chrome.

Отдельно нужно составить матрицу доступности русских TTS-голосов по устройствам.

## 9. Интеграции

### 9.1. Синтез речи

MVP:

- использовать Web Speech API там, где он доступен;
- выбирать русский голос при наличии;
- показывать предупреждение при отсутствии русского голоса;
- дать настройку скорости и высоты, если браузер поддерживает.

Риск: качество и наличие русских голосов зависят от ОС, браузера и установленных голосовых пакетов. Это нужно проверить на целевых устройствах до пилота.

### 9.2. Пиктограммы

Варианты:

1. Встроить небольшой стартовый набор собственных или открыто лицензированных пиктограмм.
2. Разрешить загрузку фотографий и изображений пользователем.
3. После MVP рассмотреть интеграцию с внешними библиотеками символов при наличии совместимой лицензии.

Нельзя включать коммерческие наборы символов без проверки лицензии.

### 9.3. Eye-gaze

MVP не должен зависеть от конкретного айтрекера. Для будущего расширения:

- поддержать dwell-select как универсальную модель выбора;
- принимать координаты взгляда через адаптер, если устройство/SDK позволяет;
- предусмотреть режим "тестовая точка" для калибровки выбора;
- хранить inputMethod = eyeGaze в событиях.

### 9.4. Кнопки и переключатели

Для MVP достаточно клавиатурной навигации. Для расширения:

- настройка одной клавиши как подтверждения;
- автоматическое сканирование;
- ручное сканирование;
- поддержка внешних кнопок, которые эмулируют Space/Enter/Tab.

## 10. Пользовательские роли и права

MVP может работать без учетных записей.

Локальные роли:

- **Пользовательский режим**: выбор карточек, сбор и озвучивание фраз.
- **Режим редактирования**: изменение досок, карточек и настроек.
- **Административный режим после MVP**: управление несколькими специалистами, облачная синхронизация, права доступа.

Вход в режим редактирования в MVP защищается простым удержанием кнопки или подтверждением, чтобы пользователь случайно не изменил доску.

## 11. Требования к интерфейсу

### 11.1. Главный экран

Содержит:

- строку фразы сверху или снизу;
- сетку карточек;
- кнопку "Домой";
- кнопку "Назад";
- кнопку "Очистить";
- кнопку входа в режим редактирования, скрытую или вынесенную из основной зоны выбора.

### 11.2. Карточка

Карточка должна содержать:

- изображение или крупный текст;
- подпись;
- цветовую маркировку, если задана;
- визуальное состояние фокуса/выбора.

### 11.3. Режим редактирования

Должен позволять:

- добавлять карточку;
- редактировать карточку;
- добавлять доску;
- менять размер сетки;
- менять порядок карточек;
- загружать изображение;
- проверять озвучку до сохранения.

### 11.4. Настройки доступа

Должны включать:

- размер сетки;
- размер текста;
- тему;
- задержку повторного нажатия;
- подтверждение выбора;
- включение/выключение строки фразы;
- параметры TTS.

## 12. Критерии приемки MVP

### 12.1. Коммуникация

- Пользователь может открыть домашнюю доску и выбрать карточку.
- Приложение озвучивает выбранную карточку на русском языке, если русский TTS доступен.
- Пользователь может собрать фразу минимум из 3 карточек и озвучить ее целиком.
- Пользователь может удалить последний элемент и очистить фразу.

### 12.2. Настройка

- Специалист может создать новую доску.
- Специалист может добавить карточку с текстом.
- Специалист может добавить карточку с изображением.
- Специалист может добавить карточку с фотографией с устройства.
- Специалист может настроить размер сетки.
- Изменения сохраняются после перезагрузки страницы.

### 12.3. Доступность

- Приложением можно пользоваться мышью, сенсорным экраном и клавиатурой.
- Видимый фокус появляется на каждой карточке при клавиатурной навигации.
- Пользователь может включить высококонтрастную тему.
- Пользователь может увеличить задержку повторного выбора.

### 12.4. Данные

- Профиль экспортируется в файл.
- Экспортированный профиль импортируется обратно без потери досок и карточек.
- При поврежденном файле импорта система показывает понятную ошибку и не перезаписывает текущие данные.

### 12.5. Статистика

- Система фиксирует выбор карточек.
- Специалист видит список наиболее часто выбранных карточек за период.

## 13. Тестирование

### 13.1. Функциональные тесты

- создание профиля;
- создание доски;
- создание карточки;
- переход между досками;
- сбор фразы;
- озвучивание карточки;
- озвучивание фразы;
- импорт/экспорт профиля;
- восстановление после перезагрузки.

### 13.2. Accessibility-тесты

- полное прохождение основного сценария с клавиатуры;
- проверка видимого фокуса;
- проверка контраста;
- проверка крупных зон на планшете;
- проверка защиты от двойного случайного нажатия.

### 13.3. Проверка на устройствах

Минимальная матрица:

- Windows + Chrome/Edge;
- Android tablet + Chrome;
- iPad + Safari;
- ноутбук с touch screen, если доступен.

Для каждого устройства фиксировать:

- доступен ли русский TTS;
- какие голоса доступны;
- работает ли fullscreen;
- сохраняются ли данные;
- работает ли импорт/экспорт.

### 13.4. Пилот со специалистом

Перед расширением функциональности провести пилот:

- минимум 3 профиля с разным уровнем доступа;
- минимум 2 занятия на профиль;
- фиксация сложностей специалиста при редактировании;
- фиксация ошибок выбора пользователем;
- сбор списка карточек, которых не хватает в стартовом наборе.

## 14. Риски и ограничения

| Риск | Влияние | Митигирующее действие |
| --- | --- | --- |
| Русский TTS недоступен или низкого качества на части устройств | Пользователь не получает голосовую обратную связь | Проверить матрицу устройств, дать инструкцию по установке голосов, рассмотреть внешние TTS после MVP |
| Слишком сложный режим редактирования | Семья и логопед не смогут поддерживать словарь | Делать редактирование пошаговым, добавить шаблоны карточек и предпросмотр |
| Нет лицензии на качественные пиктограммы | Нельзя легально включить нужные символы | Использовать открытые наборы/собственные изображения, разрешить пользовательские фото |
| Eye-gaze требует аппаратной интеграции | Функция может задержать MVP | Вынести eye-gaze в расширение, сначала реализовать универсальный dwell-select и клавиатурный доступ |
| Пользователь случайно меняет настройки | Потеря рабочей доски на занятии | Отделить пользовательский режим от редактирования, добавить подтверждения и экспорт профиля |
| Потеря локальных данных | Потеря индивидуального словаря | Сделать явный экспорт/резервную копию и напоминание о backup |

## 15. Открытые вопросы к Ольге

1. Для какого возраста и профиля пользователей нужно решение в первую очередь?
2. Нужна ли разработка именно собственного продукта или подбор/адаптация существующих решений?
3. Какие устройства уже есть у семьи/центра: Windows, iPad, Android, интерактивная панель?
4. Нужен ли айтрекер на первом этапе или это будущий сценарий?
5. Должно ли приложение работать без интернета всегда?
6. Нужны ли готовые русские наборы карточек по темам занятий?
7. Нужна ли статистика для отчетности или достаточно наблюдений специалиста?
8. Кто будет основным редактором словаря: логопед, родитель, педагог?
9. Требуется ли работа с несколькими детьми в одном учреждении?
10. Есть ли требования по хранению персональных данных и фотографий?

## 16. Рекомендуемая последовательность разработки

1. Прототип пользовательского режима:
   - домашняя доска;
   - карточки;
   - строка фразы;
   - русская озвучка.
2. Режим редактирования:
   - создание досок;
   - создание карточек;
   - загрузка фото;
   - настройки сетки.
3. Локальное хранение и экспорт/импорт профиля.
4. Настройки доступности и клавиатурная навигация.
5. Статистика использования.
6. Пилот с логопедом и 2-3 пользователями.
7. Расширения: сканирование, eye-gaze, облачная синхронизация, библиотека готовых словарей.

## 17. Минимальный стартовый словарь для MVP

Рекомендуемые доски:

- **Быстрые ответы**: да, нет, не знаю, еще, стоп, помоги, хочу, не хочу.
- **Потребности**: пить, есть, туалет, больно, устал, холодно, жарко.
- **Эмоции**: рад, грустно, страшно, злюсь, нравится, не нравится.
- **Люди**: мама, папа, бабушка, дедушка, логопед, учитель.
- **Действия**: играть, смотреть, слушать, читать, идти, сидеть, открыть, закрыть.
- **Занятие**: повтори, покажи, выбери, правильно, ошибка, перерыв.

Для каждого пользователя словарь должен адаптироваться под реальные предметы, людей и ситуации.

## 18. Definition of Done для MVP

MVP считается готовым, если:

- реализованы все требования с приоритетом MVP из раздела 6;
- выполнены критерии приемки из раздела 12;
- приложение проверено минимум на Windows Chrome/Edge и одном планшете;
- подготовлена инструкция для логопеда по созданию профиля и карточек;
- подготовлена инструкция для семьи по запуску, выбору карточек и резервному копированию;
- проведен пилотный прогон на тестовом профиле с не менее чем 30 карточками;
- известные ограничения задокументированы перед передачей пользователям.
