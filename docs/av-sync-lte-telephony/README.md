# Тестирование рассинхрона голоса и видео при классической LTE-телефонии

Комплект описывает, **как организовать лабораторный и полевой тест**, чтобы измерить рассинхронизацию (A/V offset) между:

- **видео** — идёт по IP / WebRTC / мобильному **data**-каналу;
- **голосом** — идёт отдельным путём через **классическую LTE-телефонию (VoLTE / IMS voice)**.

Это split-path сценарий: разные bearer’ы, разная приоритезация (обычно QCI=1 для голоса vs default data для видео), разные jitter buffer и playout. Именно относительный offset на ушах/глазах пользователя и нужно измерять.

## Как читать

1. [План теста](test-plan.md) — цели, сценарии, роли, критерии готовности.
2. [Лабораторный стенд](lab-setup.md) — схема стенда, эмуляция VoLTE-delay, полевой прогон.
3. [Метод измерения](measurement-method.md) — маркеры flash+beep, запись приёмника, расчёт offset.
4. [Метрики и пороги](metrics-and-thresholds.md) — что считать pass/fail.
5. Инструмент: [`tools/av_sync_measure`](../../tools/av_sync_measure/README.md).

## Короткий ответ

1. На стороне говорящего воспроизводить **синхронный стимул**: белая вспышка на видео + короткий бип в голосовой канал.
2. Убедиться, что голос реально идёт по **VoLTE** (не Wi‑Fi Calling, не CSFB в 3G/2G, не VoIP внутри того же data-приложения — если цель именно классическая телефония LTE).
3. На слушателе **записать экран + звук из динамика/линии**.
4. Найти пары «вспышка ↔ бип» и посчитать `offset_ms = t_audio - t_video`.
5. Сравнить с порогами lip-sync (ориентир комфорта: звук не раньше видео > ~45 ms и не позже > ~125 ms).

## Главная формула

```text
AV_offset_ms = T_playout_audio - T_playout_video
```

- `AV_offset_ms > 0` — голос **позже** видео.
- `AV_offset_ms < 0` — голос **раньше** видео.

```text
D_audio = T_playout_audio - T_capture_audio   # VoLTE mouth-to-ear вклад
D_video = T_playout_video - T_capture_video   # WebRTC/data вклад
AV_offset ≈ D_audio - D_video                 # если захват синхронен
```

## Типичные порядки величин (ориентиры)

| Путь | Ожидаемый вклад |
|---|---|
| VoLTE mouth-to-ear (хорошая LTE) | часто ~150–250 ms |
| VoLTE в плохих радиоусловиях / handover | 250–400+ ms, растёт jitter |
| WebRTC video over LTE data | сильно зависит от буфера/FPS; часто сопоставимо или меньше голоса |
| Итоговый A/V offset без компенсации | обычно десятки–сотни ms, знак зависит от того, чей playout «тяжелее» |

В отличие от спутника, здесь offset **не обязан** быть огромным; зато он чувствителен к радио, QCI, handover и размеру видеобуфера.

## Когда какой режим

| Режим | Когда | Что даёт |
|---|---|---|
| Эмуляция delay только на аудио | CI / офис / отладка компенсации | воспроизводимый offset |
| Реальная VoLTE | приёмочные / полевые | реальный IMS/RAN latency и jitter |
| Инструментизация клиента | есть доступ к коду | онлайн-мониторинг; marker-метод всё равно как ground truth |

## Артефакты прогона

- запись приёмника (`receiver_capture.mkv` / `.mp4`);
- JSON-отчёт (`report.json`);
- протокол стенда: оператор, VoLTE/IMS confirmation, RSRP/RSRQ если есть, кодек AMR-WB/NB, компенсация on/off;
- версия клиента и явное подтверждение, что голос шёл через классическую LTE-телефонию.
