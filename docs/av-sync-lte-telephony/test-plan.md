# План теста: рассинхрон при классической LTE-телефонии

## 1. Цель

Измерить рассинхронизацию между видео (data/IP) и голосом (**VoLTE / классическая LTE-телефония**).

Вопросы теста:

1. Какой `median_offset_ms` на приёмнике?
2. Насколько стабилен sync (`std`, drift)?
3. Укладывается ли UX в порог lip-sync?
4. Помогает ли компенсация (задержка видео / lip-sync buffer)?

## 2. Гипотеза

```text
Video: camera -> app/WebRTC over LTE data bearer -> display
Audio: mic    -> VoLTE/IMS (QCI=1)              -> speaker
```

Потоки независимы, поэтому A/V offset ≠ 0 даже при «хорошей» сети. Голос часто **позже** видео, но знак нужно измерять, не предполагать.

## 3. Объект тестирования

- Клиент видеозвонка со split-path: видео по data, голос через телефонию LTE.
- Опционально: компенсация рассинхрона в клиенте.

## 4. Не цели

- MOS/PESQ/POLQA качества речи.
- VMAF/PSNR видео.
- Полный AEC-тест (кроме влияния на детект маркеров).

## 5. Роли

| Роль | Задачи |
|---|---|
| Оператор A | стимул / хлопок перед камерой |
| Оператор B | запись экрана+звука, условия радио |
| Аналитик | `av_sync_measure`, отчёт |
| Инженер связи | подтвердить VoLTE (не Wi‑Fi Calling / не CSFB) |

## 6. Сценарии

### S1. Baseline: оба потока по IP

Аудио и видео в одном WebRTC/data-пути. Калибровка стенда записи.

**Ожидание:** `|AV_offset|` мал после вычитания recorder bias (обычно < 40–60 ms).

### S2. Эмуляция VoLTE-delay на аудио

Видео — IP. На аудио добавляется delay 150 / 250 / 350 ms ± jitter.

**Ожидание:** измеренный offset ≈ заданной задержке ± погрешность.

### S3. Реальная классическая LTE-телефония (VoLTE)

Голос через VoLTE, видео через data.

**Ожидание:** стабильный измеримый offset; фиксируем mean/p95/std и radio conditions.

### S4. Компенсация включена

Как S2/S3, но клиент выравнивает playout (обычно delay video ≈ offset).

**Ожидание:** `|median_offset|` в продуктовом бюджете.

### S5. Длинная сессия / мобильность

15–30 минут; желательно с перемещением или сменой соты.

**Ожидание:** увидеть drift и скачки offset на handover.

### S6. Негатив: не тот голосовой путь

Принудительно Wi‑Fi Calling или CSFB (если доступно) — чтобы поймать ложные прогоны и проверить детектор маршрута.

## 7. DoR

- Подтверждён VoLTE-маршрут голоса (индикатор HD Voice / VoLTE, IMS reg, engineering menu, CDR/SIP).
- Data для видео не отключён.
- Можно писать экран + **тот звук, который слышит пользователь**.
- Есть стимул flash+beep или ручной протокол хлопка.

## 8. DoD

1. сырая запись приёмника;
2. `report.json` (`median_offset_ms`, `p95`, `std`, `match_rate`);
3. протокол стенда с подтверждением VoLTE;
4. вердикт `PASS` / `FAIL` / `MEASURED_ONLY`.

## 9. Матрица прогонов (минимум)

| ID | Путь аудио | Путь видео | Компенсация | Длительность | Повторы |
|---|---|---|---|---|---|
| S1-a | IP | IP | off | 2 мин | 2 |
| S2-150 | delay 150 ms | IP | off | 2 мин | 2 |
| S2-250 | delay 250 ms | IP | off | 2 мин | 2 |
| S2-350 | delay 350 ms | IP | off | 2 мин | 2 |
| S3-volte | VoLTE real | LTE data | off | 5 мин | 3 |
| S4-comp | VoLTE or emu | LTE data | on | 5 мин | 2 |
| S5-drift | VoLTE | LTE data | on/off | 20 мин | 1 |

## 10. Ручной smoke

1. A в кадре хлопает раз в ~5 с.
2. B пишет экран+звук 60–120 с.
3. Разметка вручную или детектор motion+onset.

Автоматический flash+beep предпочтительнее.

## 11. Риски

| Риск | Влияние | Митигация |
|---|---|---|
| Голос ушёл в Wi‑Fi Calling / CSFB | не тот объект теста | проверить VoLTE до и после прогона |
| Запись с микрофона комнаты | ложный offset | internal audio / line-in / OBS desktop audio |
| AMR-NB/NS режет бип | низкий `match_rate` | 1 kHz, громче, 60–80 ms, отключить NS если можно |
| Handover посреди прогона | скачок offset | пометить в notes; отдельный S5 |
| Низкий FPS записи | ±1 кадр ошибки | ≥30 fps, лучше 60 |
