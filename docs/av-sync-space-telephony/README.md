# Тестирование рассинхрона голоса и видео при космической телефонии

Комплект описывает, **как организовать лабораторный и полевой тест**, чтобы измерить рассинхронизацию (A/V offset) между:

- **видео** — обычно идёт по IP / WebRTC / мобильному data-каналу;
- **голосом** — идёт отдельным путём через **космическую (спутниковую) телефонию**.

Разные пути = разная задержка, разный джиттер-буфер, разный clock drift. Именно это и нужно измерять, а не «кажется, губы не совпадают».

## Как читать

1. [План теста](test-plan.md) — цели, сценарии, роли, критерии готовности.
2. [Лабораторный стенд](lab-setup.md) — схема стенда, эмуляция спутника, полевой прогон.
3. [Метод измерения](measurement-method.md) — маркеры flash+beep, запись приёмника, расчёт offset.
4. [Метрики и пороги](metrics-and-thresholds.md) — что считать pass/fail.
5. Инструмент: [`tools/av_sync_measure`](../../tools/av_sync_measure/README.md).

## Короткий ответ

Самый надёжный способ без глубокой инструментизации приложения:

1. На стороне говорящего воспроизводить **синхронный стимул**: белая вспышка на видео + короткий звуковой бип.
2. На стороне слушателя **записать экран + звук из динамика/линии**.
3. Автоматически найти пары «вспышка ↔ бип» и посчитать `offset_ms = t_audio - t_video`.
4. Сравнить с порогами ITU/BT (примерно: звук опережает видео ≤ 45 ms, отстаёт ≤ 125 ms — для комфортного восприятия; для спутника часто будет хуже, и это нормально фиксировать как факт).

## Главная формула

Для одного и того же события на источнике:

```text
AV_offset_ms = T_playout_audio - T_playout_video
```

- `AV_offset_ms > 0` — голос **позже** видео (типично для спутникового uplink/downlink).
- `AV_offset_ms < 0` — голос **раньше** видео.

Отдельно полезно знать абсолютные one-way delay:

```text
D_audio = T_playout_audio - T_capture_audio
D_video = T_playout_video - T_capture_video
AV_offset ≈ D_audio - D_video   (если захват синхронен)
```

## Когда какой режим

| Режим | Когда | Что даёт |
|---|---|---|
| Эмуляция sat-delay на аудио | CI / офис / отладка компенсации | воспроизводимый offset без реального спутника |
| Реальная космическая телефония | приёмочные / полевые испытания | реальный latency/jitter/PLC |
| Инструментизация клиента (RTP/NTP timestamps) | если есть доступ к коду клиента | непрерывный мониторинг в проде |

## Артефакты прогона

Каждый прогон должен оставлять:

- запись приёмника (`receiver_capture.mkv` / `.mp4`);
- JSON-отчёт измерения (`report.json`);
- параметры стенда (тип спутника GEO/LEO, эмулированная задержка, кодеки, jitter buffer);
- версию клиента видеозвонка и режим маршрутизации голоса.
