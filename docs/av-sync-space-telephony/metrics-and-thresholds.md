# Метрики и пороги

## 1. Основные метрики

| Метрика | Определение |
|---|---|
| `offset_i_ms` | `t_beep_i - t_flash_i` для каждой сопоставленной пары маркеров |
| `mean_offset_ms` | среднее по парам |
| `median_offset_ms` | медиана (устойчивее к выбросам) |
| `p95_offset_ms` | 95-й перцентиль |
| `std_offset_ms` | стандартное отклонение (стабильность sync) |
| `drift_ms_per_min` | наклон `offset(t)` за длинную сессию |
| `match_rate` | доля вспышек, для которых найден бип |

## 2. Пороги восприятия (ориентиры)

По распространённым рекомендациям в духе ITU-R BT.1359 / индустрии lip-sync:

| Состояние | Ориентир | Комментарий |
|---|---|---|
| Комфортно | звук не раньше видео более чем на ~45 ms; не позже чем на ~125 ms | субъективно «губы совпадают» |
| Заметно | \|offset\| выше комфортной зоны | диалог ещё возможен |
| Ломает UX | offset ≳ 200–300+ ms | сложно говорить по очереди |
| Спутниковый голос без компенсации | часто 300–700+ ms | ожидание для GEO; фиксировать как baseline |

Для продукта с космической телефонией разумны **два порога**:

1. **`MEASURED_ONLY` / engineering baseline** — просто измерить факт без pass/fail.
2. **`PRODUCT_PASS`** — после компенсации попасть в комфортную зону или в свой продуктовый бюджет (например `|median_offset| ≤ 100 ms`).

## 3. Рекомендуемые вердикты в отчёте

Инструмент использует профили:

### `itu_like` (строгий UX)

- PASS, если `-45 <= median_offset_ms <= 125` и `std_offset_ms <= 40`
- иначе FAIL

### `sat_compensated` (практичный для sat + video delay)

- PASS, если `abs(median_offset_ms) <= 100` и `std_offset_ms <= 60`
- иначе FAIL

### `baseline` (только измерение)

- всегда `MEASURED_ONLY`

Выбор профиля: `--threshold-profile`.

## 4. Дополнительные наблюдения

Записывайте рядом с A/V offset (не блокируют вердикт, но объясняют его):

- one-way voice delay (если есть ping/диагностика канала);
- размер jitter buffer на приёме;
- FPS видео и число freeze;
- факты handover / перестройки кодека;
- включён ли AEC/NS/AGC.

## 5. Минимум статистики

- Не меньше **15 успешно сопоставленных маркеров** для короткого прогона.
- Для S5-drift — маркеры на всём интервале, чтобы оценить наклон.
- Если `match_rate < 0.7` — сначала чинить стимул/запись, не интерпретировать offset.
