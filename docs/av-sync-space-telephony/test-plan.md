# План теста: рассинхрон голоса и видео

## 1. Цель

Измерить и задокументировать **рассинхронизацию между видео и голосом**, когда голос проходит через космическую телефонию, а видео — по отдельному IP-пути.

Тест отвечает на вопросы:

1. Какой средний A/V offset на приёмнике?
2. Насколько он стабилен (jitter offset / drift)?
3. Укладывается ли UX в приемлемые пороги?
4. Помогает ли компенсация (задержка видео / lip-sync buffer) и на сколько?

## 2. Гипотеза

При раздельных путях:

```text
Video: camera -> IP/WebRTC -> display
Audio: mic    -> space telephony -> speaker
```

голос систематически **отстаёт** от видео на величину порядка:

- GEO: сотни миллисекунд (часто 250–700+ ms one-way в зависимости от сегмента);
- LEO: десятки миллисекунд, но с переменным jitter и handovers.

## 3. Объект тестирования

- Клиент видеозвонка (оба конца: A говорит, B смотрит/слушает).
- Режим маршрутизации: **видео по data/IP**, **аудио по космической телефонии**.
- Опционально: механизм компенсации рассинхрона в клиенте (если есть).

## 4. Не цели этого теста

- Качество речи MOS / PESQ / POLQA (отдельный тест).
- Качество видео (PSNR/VMAF) — только timing.
- Полная оценка эхоподавления / AEC (кроме влияния на детект маркеров).

## 5. Роли

| Роль | Задачи |
|---|---|
| Оператор A (sender) | запускает стимул или говорит/хлопает перед камерой |
| Оператор B (receiver) | пишет экран+звук, фиксирует условия |
| Аналитик | прогоняет `av_sync_measure`, оформляет отчёт |
| Инженер связи | подтверждает, что голос реально идёт через sat-путь |

## 6. Сценарии

### S1. Baseline без спутника

Оба потока (аудио и видео) по обычному IP. Нужен как нулевая точка калибровки стенда записи.

**Ожидание:** `|AV_offset|` мал (обычно < 40–60 ms после калибровки стенда).

### S2. Эмуляция космической задержки на аудио

Видео — обычный IP. На аудио-путь добавляется фиксированная задержка (например 300 / 500 / 700 ms) + опционально jitter.

**Ожидание:** измеренный offset ≈ заданной задержке ± погрешность стенда.

### S3. Реальная космическая телефония

Голос через боевой/стендовый sat-канал. Видео — IP.

**Ожидание:** стабильный положительный offset (голос позже); фиксируем mean/p95/max и drift за сессию.

### S4. Компенсация включена

Как S2/S3, но клиент задерживает видео (или иначе выравнивает playout).

**Ожидание:** `|AV_offset|` уменьшается до целевого бюджета.

### S5. Длинная сессия (drift)

15–30 минут разговора/стимула. Проверяем уход синхронизации из-за clock skew и смены буферов.

## 7. Входные условия (DoR)

- Известен маршрут голоса (подтверждение от инженера связи / CDR / SIP/IMS traces).
- На приёмнике можно записать **экран видеозвонка** и **звук, который реально слышит пользователь**.
- Есть либо генератор стимула (`generate_stimulus`), либо согласованный ручной протокол (хлопок/клаппер).
- Синхронизированы часы стенда хотя бы для маркировки начала прогона (NTP достаточно для метаданных; для измерения offset часы отправителя не обязательны в marker-методе).

## 8. Выходные условия (DoD)

На каждый прогон есть:

1. сырая запись приёмника;
2. `report.json` с `mean_offset_ms`, `p95_offset_ms`, `std_offset_ms`, числом маркеров;
3. заполненный протокол стенда (см. [lab-setup](lab-setup.md));
4. вердикт: `PASS` / `FAIL` / `MEASURED_ONLY` относительно выбранного порога.

## 10. Ручной smoke (если нет генератора)

1. А стоит перед камерой с видимыми руками.
2. Каждые ~5 секунд делает громкий хлопок в ладоши в кадре (руки в центре).
3. B пишет экран+звук 60–120 секунд.
4. Аналитик либо размечает хлопки вручную в таймлайне, либо использует детектор (яркий motion + audio onset).

Автоматический flash+beep предпочтительнее: меньше ошибок и выше точность.

## 11. Риски и как их снять

| Риск | Влияние | Митигация |
|---|---|---|
| Запись звука с микрофона комнаты, а не из динамика | ложный offset / эхо | line-in / virtual cable / «stereo mix» / отдельный recorder на выход |
| AGC/NS режет бипы | пропуск маркеров | громче бип, проще спектр (1 kHz), отключить NS на время теста |
| Низкий FPS записи экрана | ошибка ±1 кадр | писать ≥30 fps, лучше 60; учитывать quantize error |
| Голос на самом деле не через sat | бессмысленный результат | проверка маршрута до прогона |
| Эхо/sidetone | ложные audio onsets | использовать гарнитуру / отключить speakerphone |
