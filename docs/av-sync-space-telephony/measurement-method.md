# Метод измерения A/V offset

## 1. Идея

На источнике одновременно возникают два маркера одного события:

- **видео-маркер** — короткая белая вспышка кадра (flash);
- **аудио-маркер** — короткий тон (beep).

На приёмнике оба маркера приходят разными путями. Разница времён их появления в записи и есть рассинхрон, который слышит/видит пользователь.

```text
AV_offset_ms = t_beep_playout - t_flash_playout
```

## 2. Почему этот метод подходит для космической телефонии

- Не требует одинаковых NTP-часов на A и B.
- Не зависит от внутренних RTP timestamp’ов (их может не быть на sat voice path).
- Измеряет **end-to-end playout**, включая jitter buffer, decoder, render.
- Работает даже если аудио идёт через «чужой» голосовой контур (IMS/PSTN/sat gateway).

## 3. Параметры стимула (рекомендуемые)

| Параметр | Значение | Зачем |
|---|---|---|
| Период маркера | 3–5 s | чтобы успевать разносить пары |
| Длительность flash | 1–2 кадра (≈33–66 ms @30fps) | уверенный детект яркости |
| Длительность beep | 40–80 ms | уверенный onset без «мазни» |
| Частота beep | 1000 Hz | просто спектр, переживает кодеки |
| Амплитуда | высокая, без клиппинга | против NS/AGC |
| Длина ролика | 60–180 s | 20–50 маркеров на статистику |

Генератор: `python3 -m tools.av_sync_measure generate`.

## 4. Как гонять

### Подготовка

1. Откалибровать recorder bias (см. [lab-setup](lab-setup.md)).
2. На A подать стимул в камеру/микрофон клиента:
   - ideal: virtual camera + virtual mic;
   - simple: полный экран стимула перед камерой + звук в микрофон с динамиков (хуже из-за акустики).
3. На B открыть звонок на весь экран / стабильное окно.
4. Начать запись на B, затем старт стимула на A.
5. Писать не меньше 60 секунд полезного сигнала.

### Раздельные пути

Убедиться, что:

- видеозвонковый клиент реально показывает видео A;
- голос A доходит именно через космическую телефонию / эмулятор;
- на B в запись попадает тот же звук, что играет в уши пользователю.

## 5. Автоматический разбор записи

```bash
python3 -m tools.av_sync_measure measure \
  --input receiver_capture.mkv \
  --bias-ms 18 \
  --report report.json
```
Алгоритм инструмента:

1. Достаёт аудио (ffmpeg → PCM WAV 48 kHz mono).
2. Считает огибающую и ищет onsets бипов.
3. Сэмплирует яркость кадров (или центрального ROI) и ищет вспышки.
4. Жадно сопоставляет ближайшие flash↔beep в окне поиска (по умолчанию ±2000 ms — с запасом под GEO).
5. Считает raw offsets, вычитает `--bias-ms`.
6. Печатает mean / median / p95 / std и вердикт по порогам.

## 6. Интерпретация знака

| Offset | Смысл | Типичная причина в вашем кейсе |
|---|---|---|
| `+480 ms` | голос позже видео на 480 ms | sat audio delay > video delay |
| `-30 ms` | голос чуть раньше видео | видеобуфер больше / компенсация перестаралась |
| растёт со временем | drift | разные clock / растяжение буфера |

Для космической телефонии **положительный offset ожидаем**. Задача продукта — либо честно показать задержку, либо компенсировать (обычно задержкой видеоподложки до голоса).

## 7. Точность и погрешность

Бюджет ошибки примерно:

```text
± 0.5 video frame   (например ±16.7 ms @60fps записи)
± onset detector    (обычно несколько ms на чистом бипе)
± recorder bias     (убирается калибровкой)
```

Для GEO-задержек в сотни ms такой точности достаточно, чтобы принимать продуктовые решения.

Если offset около порога ITU (десятки ms) — пишите приёмник на 60 fps и используйте больше маркеров.

## 8. Альтернативы (если marker-метод нельзя)

### 8.1 Хлопок в кадре

Человек хлопает. Дальше — ручная разметка или детектор motion+onset. Грубее, но работает в поле без подготовки.

### 8.2 Инструментизация клиента

Логировать:

- `audio_capture_ts`, `audio_playout_ts`
- `video_capture_ts`, `video_frame_render_ts`

Тогда offset считается онлайн. Нужен доступ к коду и общая шкала времени (RTP+NTP / clock monotonic с синхронизацией). Для sat voice path timestamps часто теряются на gateway — marker-метод всё равно нужен как ground truth.

### 8.3 Внешняя высокоскоростная камера

Снимать экран и светодиод/осциллограф на audio out. Избыточно для большинства продуктовых тестов.

## 9. Что делать с результатом в продукте

1. Если mean offset стабильно > 125 ms — включать **video delay buffer** ≈ mean offset (или EMA).
2. Если std большой — сначала стабилизировать jitter buffer голоса, потом sync.
3. Если drift — периодически переоценивать offset по редким маркерам/voice activity vs lip motion (уже research-уровень).
