# AGENTS.md — правила работы агентов в этом хранилище

Это личное рабочее пространство технического лидера. Хранилище — источник правды; Jira, Confluence, почта и чаты — внешние системы и витрины.

## 1. Язык и стиль
- Все заметки, саммари и отчёты — на русском.
- Даты в формате ISO: `YYYY-MM-DD`.
- Ссылки внутри хранилища — относительные; вики-ссылки Obsidian допустимы.

## 2. Чувствительность данных
| Контур | Уровень по умолчанию | Допустимые модели |
|---|---|---|
| `directions/`, `reporting/`, `presentations/`, `inbox/` | обычный | облачные (Cursor/Claude) |
| `people/`, `budget/` | internal | только внутренняя модель (OpenAI-compatible endpoint) |
| любой файл с `sensitivity: internal` во frontmatter | internal | только внутренняя модель |

- Правило файла (`sensitivity: internal`) важнее правила папки.
- Содержимое internal-файлов никогда не попадает в промпты облачных моделей — ни целиком, ни выдержками.
- В саммари и дашборд из internal-контуров выносятся только нейтральные формулировки без персональных оценок и сумм.

## 3. Секреты
- Значения секретов (`INTERNAL_LLM_KEY`, `JIRA_TOKEN`, `CONFLUENCE_TOKEN` и др.) живут только в переменных окружения на машине пользователя.
- Агентам запрещено: читать значения этих переменных, выводить их, копировать в файлы, передавать в промпты.
- В хранилище допустимы только имена переменных (см. `integrations/README.md`).

## 4. Внешние системы
- Чтение (Jira, Confluence, веб-ссылки) — свободно.
- Любая запись во внешние системы (публикация в Confluence, комментарии в Jira, отправка почты) — только по явной команде пользователя в текущем диалоге.

## 5. Флот (`fleet/`)
- Задачи для агентов оформляются файлами по шаблону `fleet/_template-task.md`.
- Агент обязан вести раздел «Ход работы» и обновлять `state` и `updated` в frontmatter.
- Нужен ответ или решение пользователя → `state: needs-me`, один конкретный вопрос в разделе «Вопрос ко мне», работа приостанавливается. Агент не копит вопросы.
- Задачи про внутренние системы или internal-данные → `model: internal`, выполняются внутренней моделью с ноутбука.

## 6. Входящие (`inbox/`)
- Сырые источники не правятся. Результат обработки — саммари по шаблону `inbox/_template-summary.md` и разнесение по контурам; после этого файл переносится в `inbox/processed/`.
- Если в источнике обсуждаются люди или деньги — саммари помечается `sensitivity: internal`.
